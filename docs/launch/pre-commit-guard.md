# دليل حارس ما قبل الالتزام (Pre-commit Guard) — بيانات العملاء والأسرار

**التاريخ:** 2026-09-03 · **الفرع:** recovery/stabilization-2026-08-23

## لماذا
بتاريخ 2026-09-02 وصل ملف توثيق يضم 22 عنوان بريد لعملاء حقيقيين إلى تاريخ git، واحتاج الأمر filter-branch لتطهيره قبل أول push للفرع. هذا الحارس يمنع تكرار هذا الصنف من التسريب آلياً عند كل `git commit`.

## التثبيت (مرة واحدة لكل نسخة محلية)
```
git config core.hooksPath .githooks
```
على macOS/Linux تأكد أن الملف قابل للتنفيذ: `chmod +x .githooks/pre-commit` (على NTFS/ويندوز لا يوجد "exec bit"؛ Git for Windows يشغّله عبر sh.exe المرفق بغض النظر عن ذلك).

## الملفات
- `.githooks/pre-commit` — سكربت sh بسيط (نهايات أسطر LF)، ينفّذ `pii-guard.mjs` عبر `exec node` وينهي بنفس رمز الخروج.
- `.githooks/pii-guard.mjs` — الماسح الفعلي (Node ESM، بدون أي حزمة خارجية إضافية).

## ما الذي يُحجب
1. **عناوين بريد غير مُدرجة في القائمة البيضاء** — أي عنوان يظهر في سطر مُضاف (+) ضمن diff الالتزام المرحلي (`git diff --cached --unified=0`) ولا يطابق قواعد السماح أدناه.
2. **أنماط أسرار معروفة** في أي سطر مُضاف:
   - مفاتيح Google (`AIza...`، وصيغة `AQ.` الجديدة)
   - مفاتيح OpenAI (`sk-...`)
   - مفتاح Supabase السري (`sb_secret_...`) — أما `sb_publishable_...` فمسموح (عام بالتصميم)
   - مفاتيح Moyasar/Stripe السرية (`sk_live_...`/`sk_test_...`) — أما `pk_live_...`/`pk_test_...` فمسموح (عام بالتصميم؛ الصيغة موثّقة في docs.moyasar.com/api/authentication)
   - مفاتيح Resend (`re_...`؛ الصيغة موثّقة في resend.com/docs/api-reference/api-keys)
   - كتل مفاتيح خاصة (`-----BEGIN ... PRIVATE KEY-----`)
   - سلاسل تشبه JWT (`eyJ...` بنقطتين وطول أكبر من 100 حرف)
3. **ملفات بيانات مجمّعة** — أي `.csv`/`.xlsx` في أي مكان بالشجرة، أو `.json`/`.md`/`.txt` تحت `docs/`، تُفحص بكامل محتواها المرحلي (لا الإضافات فقط) وتُحجب إذا احتوت 5 عناوين بريد مختلفة غير مُدرجة في القائمة البيضاء أو أكثر. هذا يمنع تسريب قائمة عملاء عبر عدة التزامات صغيرة (كل التزام يضيف عنواناً أو عنوانين فيبقى تحت الحد بمفرده).
   - ملاحظة صدق: فحص `.xlsx` هو "أفضل جهد" — قارئ ZIP/XML مبني داخل `pii-guard.mjs` (بدون حزمة خارجية) يقرأ `sharedStrings.xml` وملفات أوراق العمل عبر `node:zlib`؛ ملف مشفّر أو غير معتاد البنية يُتخطّى بصمت بدل حجب الالتزام كذباً. راجع مثل هذه الملفات يدوياً قبل الالتزام.

## القائمة البيضاء (لا يُحجب)
- أي عنوان على `consultx.app` أو `consultx.ai` (بما فيها النطاقات الفرعية)
- `mailnull.com`، `example.com`
- عناوين الاختبار الثابتة: `a@b.com`، `c@d.com`، `your@email.com`، `ksasmoke@ksa.com`
- أي عنوان يبدأ بـ `njajrehwaseem` أو `waseemnjajreh20` (وسيم وألقابه)
- صناديق النظام على نطاقات consultx: `noreply@`، `support@`، `info@`، `hello@`

## تجاوز إيجابي كاذب عن قصد
أضف تعليقاً بالنص الحرفي `pii-guard: allow` على نفس السطر — يُسقط كل نتائج ذلك السطر (بريد أو سر معاً). لا يوجد ولن يوجد استثناء عبر قائمة بيضاء مبنية على مفتاح حقيقي مُثبَّت في الكود — العلامة هي الآلية الوحيدة.

مثال:
```
const ANON_KEY = "eyJ..."; // pii-guard: allow — public anon key, safe to expose
```

## القاعدة الذهبية لبيانات العملاء
بيانات العملاء الحقيقية تعيش فقط تحت `docs/campaigns/` (مُدرج فعلياً في `.gitignore`، ويحوي محلياً `active-subscribers-20260901.csv` و`lapsed-users-20260901.csv`) — لا تُنقل أبداً إلى أي مسار متتبَّع بواسطة git.

## الفحص اليدوي / سطر الأوامر
```
node .githooks/pii-guard.mjs --staged            # نفس ما يشغّله الـhook تلقائياً
node .githooks/pii-guard.mjs --check-file <path>  # فحص ملف واحد بمعزل عن git (لاختبار يدوي أو CI)
```
رمز الخروج: `0` = نظيف، `1` = حُجب (النتائج مطبوعة بصيغة `file:line — reason`)، `2` = خطأ داخلي في الحارس نفسه (يُغلق آمناً، أي يُعامل كحجب أيضاً).

## الاختبارات
`src/__tests__/piiGuard.test.ts` (28 اختباراً) يغطي: القائمة البيضاء، اكتشاف البريد غير المسموح، كل نمط سر، علامة `pii-guard: allow`، قاعدة قوائم البريد المجمّعة لملفات `docs/` و`.csv`، وتحليل diff للتأكد أن الأسطر المحذوفة (-) لا تُفحص أبداً.
```
npx vitest run src/__tests__/piiGuard.test.ts
```

## قيود معروفة (صدق لا تجميل)
- لغير ملفات البيانات، الفحص يعمل على الأسطر المُضافة في diff الالتزام المرحلي فقط — تعديل قيمة داخل سطر قديم بلا إضافة سطر جديد لن يُلتقط بمسار الإضافات (ملفات البيانات مستثناة من هذا القيد لأنها تُفحص بكاملها).
- لا فحص لملفات ثنائية غير `.xlsx` (صور، PDF) بحثاً عن بريد مُضمّن نصياً.
- بادئات مفاتيح Moyasar وResend مبنية على التوثيق العلني لكل منهما وقت الكتابة، وليست مُتحقَّقة مقابل مفتاح حقيقي فعلي من حساب ConsultX.

## إعفاء ملفات الاختبار (allow-file)

ملفات الاختبار التي تحوي أنماطاً مزيفة عمداً (إيميلات ومفاتيح وهمية) تُعفى كاملةً بعلامة `pii-guard: allow-file` في أول 20 سطراً — **فقط** إن كان الملف تحت `src/__tests__/`. أي ملف توثيق أو بيانات يحمل العلامة يبقى مفحوصاً. الحارس يطبع أسماء الملفات المعفاة عند كل كوميت ليبقى الإعفاء مرئياً.
